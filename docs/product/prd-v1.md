# SmartWardrobe Web MVP PRD v1

## 1. 文档信息
- 文档名称：SmartWardrobe Web MVP PRD v1
- 版本：v1.0
- 状态：冻结
- 更新日期：2026-04-18
- 适用范围：Web 端 MVP

## 2. 产品目标
SmartWardrobe Web MVP 的目标是帮助用户把分散的服装信息集中到一个可浏览、可维护的电子衣橱中，并在录入后通过规则引擎完成基础自动分类，降低后续整理成本。

首版重点解决以下问题：
- 用户没有统一位置存放自己的服装记录。
- 录入服装后需要快速看到结果，而不是进入复杂管理流程。
- 用户希望系统先帮忙做基础分类，但保留人工修正权。

首版明确不解决以下问题：
- 不做真实多用户体系。
- 不做第三方登录。
- 不做 AI 图像识别。
- 不做穿搭推荐、日历搭配、社区分享。
- 不做批量导入、电商链接导入。

## 3. 用户画像
首版默认用户为单用户演示场景中的个人衣物管理者，具备以下特征：
- 希望把常穿服装整理成一个可视化衣橱。
- 可以接受录入时填写少量基础信息。
- 更关注“先录进去并整理好”，而不是复杂分析功能。

## 4. 产品范围
### In Scope
- 演示登录入口
- 单件服装录入
- 单张图片上传
- 服装列表展示
- 服装详情查看
- 规则自动分类
- 手动修改分类结果
- 基础筛选

### Out of Scope
- 真实注册登录
- 多用户协作
- AI 自动识图
- 推荐算法
- 批量导入
- 电商抓取
- 多语言

## 5. 核心用户流程
### 流程 1：登录进入
1. 用户访问 `/login`。
2. 用户点击“进入我的衣橱（演示版）”。
3. 系统创建演示会话。
4. 系统跳转到 `/wardrobe`。

### 流程 2：导入服装
1. 用户从衣橱主页进入 `/import`。
2. 用户上传单张服装图片。
3. 用户填写基础字段。
4. 用户提交导入。
5. 系统保存图片和服装记录。
6. 系统执行规则分类。
7. 系统跳转到服装详情页或衣橱列表页，并提示导入成功。

### 流程 3：浏览衣橱
1. 用户在 `/wardrobe` 查看服装列表。
2. 用户可按品类、季节、颜色筛选。
3. 用户点击任意服装进入详情页。

### 流程 4：修正分类
1. 用户在 `/garment/[id]` 查看自动分类结果。
2. 用户手动修改分类字段。
3. 用户保存修改。
4. 系统持久化最终结果。

## 7. 页面详细说明
### 7.1 `/login`
页面目标：提供单一清晰入口，让用户进入演示衣橱。

页面元素：
- 品牌标题：SmartWardrobe
- 页面说明：一句话说明这是电子衣橱演示版
- 主按钮：进入我的衣橱
- 辅助说明：当前为演示模式，不需要注册

交互规则：
- 点击主按钮后创建演示会话。
- 成功后跳转 `/wardrobe`。
- 若会话创建失败，显示错误提示并允许重试。

状态要求：
- 默认态
- 提交中态
- 错误态

### 7.2 `/wardrobe`
页面目标：展示当前衣橱中的服装，并提供筛选和新增入口。

页面元素：
- 页面标题
- 新增按钮：进入 `/import`
- 筛选区域：品类、季节、颜色
- 服装列表区
- 空态提示

列表卡片展示字段：
- 图片
- 名称
- 品类
- 子类
- 颜色
- 季节

交互规则：
- 点击“新增服装”进入 `/import`。
- 点击筛选条件实时更新列表。
- 点击服装卡片进入 `/garment/[id]`。

状态要求：
- 默认列表态
- 筛选后列表态
- 空衣橱空态
- 加载态
- 读取失败错误态

### 7.3 `/import`
页面目标：完成单件服装导入。

表单字段：
- 图片：必填
- 名称：必填
- 子类：必填
- 颜色：选填
- 季节：选填
- 品牌：选填
- 备注：选填

页面元素：
- 页面标题
- 返回入口
- 图片上传区
- 基础信息表单
- 提交按钮
- 取消按钮

交互规则：
- 表单校验通过后才能提交。
- 图片先上传，再保存服装记录。
- 记录保存成功后立即执行规则分类。
- 成功后跳转到新创建服装的详情页。
- 失败时保留用户已输入内容，并给出错误提示。

状态要求：
- 默认编辑态
- 校验失败态
- 上传中态
- 提交中态
- 成功态
- 失败态

### 7.4 `/garment/[id]`
页面目标：查看单件服装信息，并支持手动修正分类结果。

展示字段：
- 图片
- 名称
- 品类
- 子类
- 颜色
- 季节
- 品牌
- 备注
- 分类来源说明

可编辑字段：
- 品类
- 子类
- 颜色
- 季节
- 品牌
- 备注

交互规则：
- 用户点击编辑后进入可编辑状态。
- 用户保存后更新数据库记录。
- 保存成功后保留在当前页，并提示保存成功。

状态要求：
- 默认查看态
- 编辑态
- 保存中态
- 保存成功态
- 保存失败态
- 记录不存在态

## 8. 数据对象定义
详见字段字典文档。首版核心对象为：

- `GarmentRecord`
- `ClassificationResult`

## 9. 自动分类规则原则
- 自动分类只在导入时执行。
- 自动分类基于 `subcategory` 做主映射。
- 若用户已填写某字段，则用户输入优先。
- 规则只补全空字段，不覆盖用户明确输入。
- 用户在详情页手动修改后，该值视为最终值。

## 10. 非功能要求
- 界面语言：中文
- 终端优先级：桌面优先，移动端可用
- 响应速度：主要页面在正常网络下应保持流畅
- 可维护性：字段、规则、页面说明需与工程实现一一对应
- 一致性：列表页和详情页展示字段必须一致

## 11. 研发边界
- 研发不得自行新增业务字段。
- 研发不得自行修改分类逻辑口径。
- 产品变更必须先更新 PRD、字段字典和规则文档。
- 若实现中发现缺失定义，必须回流到产品文档补齐后再落地。

## 12. 验收原则
- 每个页面必须有明确的空态、错误态和成功反馈。
- 从登录到导入到查看到手动修正的主流程必须完整闭环。
- 所有字段、分类逻辑、提示文案必须能在产品文档中找到依据。
