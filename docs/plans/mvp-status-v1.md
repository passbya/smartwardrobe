# SmartWardrobe Web MVP 状态更新 v1

## 当前阶段

- 项目进入 `M4` 预备阶段，重点从“功能可用”转到“部署前收口”
- 当前默认运行模式仍是 `local demo`，双模式架构已经明确
- `Supabase` 迁移路径已写入工程文档，但真实部署仍受外部环境阻塞

## 已完成

- 本地完整链路已跑通：登录、导入、列表、详情、自动分类、手动修正
- 本地验证口径已收敛：`lint`、`test`、`build`、`smoke`
- 发布硬化层已落地：登录页和应用壳显示当前数据模式，`full-check` 用 `/login` 就绪信号串起生产启动和浏览器烟测
- 工程文档已拆分为产品、工程、测试和工作日志
- 后端数据层已支持 `local demo / Supabase` 双模式切换

## M4 预备目标

- 固化本地全检口径，作为后续 CI 的最小门禁
- 明确 CI 工作流应包含的检查步骤和触发条件，当前已落地到 `release-ready` workflow
- 补齐 Supabase 迁移所需的环境变量、bucket 和最小 schema 口径
- 继续保持本地 demo 可回退，避免迁移阶段把主流程打断

## 仍然阻塞

- 真实 Supabase 项目环境变量尚未接入到部署环境
- 目标 bucket `garment-images` 是否已创建、是否可访问仍待确认
- 迁移执行与预览部署尚未在真实 Supabase 环境中完成
- 真实 Supabase 仍未替代本地 demo 作为默认运行模式

## 协作规则

- 研发优先遵循冻结需求和迁移文档，不在实现阶段扩展产品范围
- 发现字段、表结构或存储路径缺口时，先补文档，再进入代码变更
- 迁移相关结论必须区分“文档已定义”和“真实环境已验证”
