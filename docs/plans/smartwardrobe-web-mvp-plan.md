# SmartWardrobe Web MVP 规划（收口版）

## Summary

- 产品需求已冻结，当前仓库已经具备可运行的本地 demo
- 本文只保留 M4 相关边界：本地全检、CI 门禁、运行时诊断、双模式架构和 Supabase 迁移阻塞
- 默认数据模式仍是 `local demo`，`Supabase` 只是下一阶段迁移目标，不等于已上线

## 当前状态

- 本地链路已完成：登录、导入、列表、详情、自动分类、手动修正
- 运行时诊断已上线：登录页和应用壳会显示当前数据模式，便于确认当前运行在本地 demo 还是 Supabase
- 文档体系已拆分为产品、工程、测试、计划和日志
- 测试口径已收口到 `lint + test + build + smoke`
- `full-check` 已成为本地发布前的统一入口，会先构建、再启动、再等待 `/login`、再跑浏览器烟测
- 数据层已经抽象出 `local demo / Supabase` 双模式切换

## M4 重点

- 把本地全检作为当前交付的最低门禁
- 明确 CI 触发步骤和发布前检查顺序，并与本地 `full-check` 保持一致
- 继续保持本地 demo 可独立运行，避免迁移阶段卡住主流程
- 为真实 Supabase 部署准备环境变量、bucket 和 schema 验证清单

## 仍待完成

- 真实 Supabase 项目环境变量接入
- `garment-images` bucket 在目标项目中的创建与连通性确认
- 迁移 SQL 在真实项目中的执行与回归验证
- 真实 Supabase 仍未替代本地 demo 作为默认运行模式

## 协作规则

- 产品冻结后，工程阶段不主动扩展新需求
- 若发现字段、表结构或路径缺口，优先补文档，再补代码
- 迁移相关表述必须区分“已定义”与“已验证”
