# SmartWardrobe 前端技术设计 v1

## 目标

前端负责页面、组件、交互和状态呈现。当前页面层已经支持完整的本地 demo 主流程，且不会因为后端切换而改变用户可见路径。

## 页面范围

- `/login`
- `/wardrobe`
- `/import`
- `/garment/[id]`

## 当前职责

- 保持登录、导入、列表、详情四个页面的稳定交互
- 保持空态、错误态、成功态和手动修正反馈清晰
- 让 UI 直接消费统一的数据接口，不关心底层是 `local demo` 还是 `Supabase`

## 运行时诊断

- 登录页和应用壳都会显示当前数据模式
- `本地 demo` 与 `Supabase` 的提示用于人工确认当前运行时状态，不是业务功能
- 这层提示是发布硬化的一部分，目的是避免把未完成迁移误看成已切换成功

## 设计原则

- 页面结构要稳定，避免后端切换导致用户路径变化
- 空态和失败态要可解释，不靠隐藏错误处理
- 本地 demo 与 Supabase 两种模式下，页面语义保持一致

## M4 关注点

- 继续保持首版体验简洁，避免在迁移阶段引入新交互
- 维持数据模式提示和页面文案一致，避免前后端口径不统一
- 维持响应式和基础可访问性
- 关注导入、分类和详情编辑的收口一致性
